# Notion provider package

Notion MCP tools (`@notionhq/notion-mcp-server` 2.5.2) behind Keystone. Each person, service, or role uses its own Notion integration token. The server code is installed from the lock file into the box `cache` volume on first start; it is not baked into the image.

## Install

```sh
keystonectl service apply notion
```

Answer the domain and certificate questions (or use `--defer-public` if the public URL is not ready yet). The manifest pins the shared `stdio-box` image and sets `BOX_PROVIDER=notion` and `BOX_COMMAND=npx -y @notionhq/notion-mcp-server@2.5.2`.

## Credential variant

| Variant | Fields | Check |
|---|---|---|
| `token` | `NOTION_TOKEN` | `GET https://api.notion.com/v1/users/me` with `Notion-Version: 2022-06-28` |

Create an integration at [notion.so/profile/integrations](https://www.notion.so/profile/integrations), copy the token, and grant the integration access to the pages it should use inside Notion.

## First profile

From chat (after the box is healthy):

1. `notion_creds_profile_create` with `{"name": "team", "variant": "token"}` — open the form link and paste `NOTION_TOKEN`.
2. `notion_creds_bind` with `{"subject": "user:you@example.com", "profile": "notion/team"}`.

Or import from a file:

```sh
docker compose exec -T notion-mcp credsctl profile import notion/shared \
  --from-file - --if-absent --no-check <<'EOF'
NOTION_TOKEN=your-token-here
EOF
docker compose exec notion-mcp credsctl bind default notion/shared
```

Replace `notion-mcp` with the MCP container name from `keystonectl service status notion --json`.

## Move from deploy `notion.env`

The old supergateway service used a single `NOTION_TOKEN` for everyone. Import that env file with `--ignore-unknown` if it contains extra keys. The `token` variant is chosen automatically when only `NOTION_TOKEN` is set.

## Roles and policy

See `policy.example.yaml` in this directory after it is generated by `stdio-box policy-example --namespace notion` (stdio-box release that includes policy templates). The box does not enforce roles: any caller your gateway policy allows to use `notion_*` can reach Notion tools, and anyone allowed `notion_creds_*` can manage every profile in this box. Do not give a broad `notion_*` allow rule to non-administrator roles.

## Upgrade the server

1. Bump `@notionhq/notion-mcp-server` in `package.json`, refresh `package-lock.json` with `npm install --package-lock-only`, and re-run `keystonectl package wrap-stdio packages/notion`.
2. Commit the new lock file and `tools.snapshot.json`.
3. Release a new stdio-box image and bump the package patch version.
